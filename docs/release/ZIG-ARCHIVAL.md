# Zig Archival Plan

This document governs the one-time move of the Zig reference implementation
into `legacy/zig/` after the Rust rewrite has completed its soak window.  No
files are moved until every soak criterion below is satisfied.

---

## 1. Context

`mkit` was originally written in Zig (0.15.x / 0.16.x).  A full Rust rewrite
landed on the `rewrite/rust` tracking branches and was merged into `main` as
Phase 10 of the rewrite project.  The Rust binary (`rust/`) is now the primary
build surface; the Zig tree (`src/`, `build.zig`, `build.zig.zon`,
`.zigversion`, `.github/workflows/ci.yml`) sits unused but is kept in the repo
root until byte-parity and release-stability are confirmed.

**Byte-parity status** (at the time this document was authored, 2026-04-23):
The Rust implementation passes all golden-vector tests generated by the Zig
harvester (`scripts/harvest/harvest.zig`).  Active parity tracking is done via
the `scripts/harvest-golden-vectors.sh` / `scripts/harvest-golden-vectors-phase8.sh`
harnesses.  No regressions have been observed since Phase 9 (mkit-cli).

---

## 2. Soak Criteria

All five criteria must be met before the archival PR is opened.  The dry-run
script (`scripts/archive-zig-dry-run.sh`) checks as many as it can
automatically; a human reviewer must confirm the remainder.

| # | Criterion | How to verify |
|---|-----------|---------------|
| 1 | Rust binary shipped in a tagged release ≥ v0.3.0. | `git tag --list 'v*' | sort -V | tail -1` shows v0.3.0 or higher. |
| 2 | No golden-vector regressions between Rust and Zig outputs for ≥ 30 consecutive days. | Check the CI run history for `rust.yml` — no `golden-vectors` job failure in the last 30 days. |
| 3 | CI Rust matrix (`rust.yml`) green on both `ubuntu-latest` and `macos-latest` for ≥ 30 consecutive days. | `gh run list --workflow rust.yml --limit 60` — all runs `completed`/`success`. |
| 4 | All previously-stubbed CLI subcommands are functional (task tracker issue #33 closed). | `gh issue view 33 --repo officialunofficial/mkit` shows `closed`. |
| 5 | No open blocker issues tagged `arch/zig-legacy`. | `gh issue list --label arch/zig-legacy --state open` returns empty. |

## 3. What Moves

Every path listed here is moved with `git mv` (preserving history) in a single
archival PR.  The script in §6 enumerates and executes these moves.

| Source | Destination | Notes |
|--------|-------------|-------|
| `src/` | `legacy/zig/src/` | Entire Zig source tree including `src/transport/` and `src/attestations/`. |
| `build.zig` | `legacy/zig/build.zig` | Top-level Zig build script. |
| `build.zig.zon` | `legacy/zig/build.zig.zon` | Zig package manifest. |
| `.zigversion` | `legacy/zig/.zigversion` | Pinned toolchain version. |
| `.github/workflows/ci.yml` | `legacy/zig/.github-workflows/ci.yml` | Renamed so GitHub does not activate it; preserved for reference only. |

> **Note:** `legacy/zig/.github-workflows/ci.yml` uses a hyphen, not a slash,
> so it is NOT in a `.github/workflows/` directory and will not be run by
> GitHub Actions.

## 5. Follow-Up Updates (post-archival PR)

These changes must land in the same archival PR or in an immediate follow-up:

1. **`scripts/verify-rename.sh` — SCAN_PATHS**: Remove `src/` (no longer a
   live path).  `legacy/zig/` does not need the rename gate applied to it
   (archived code is allowed to carry historical strings).  Keep `rust/` in
   SCAN_PATHS.

2. **`README.md` — "Zig reference build" section**: Update any path references
   from `src/` → `legacy/zig/src/` and `build.zig` → `legacy/zig/build.zig`.
   Make clear it is a historical reference, not the active build.

3. **Delete `.github/workflows/ci.yml`**: Once moved to
   `legacy/zig/.github-workflows/ci.yml`, the original path is gone.  The `git
   mv` handles this; no separate delete step is needed.

4. **Harvest script assessment**: Once a pure Rust harvester replaces
   `scripts/harvest/harvest.zig`, move or delete that file in a separate PR.

## 6. Dry-Run Script

`scripts/archive-zig-dry-run.sh` enumerates every `git mv` the archival PR
will perform and verifies the soak criteria before doing anything destructive.

Run in dry-run mode (default, no changes made):

```sh
bash scripts/archive-zig-dry-run.sh
```

Run in execute mode (actually performs the `git mv`s — only after all criteria
pass):

```sh
bash scripts/archive-zig-dry-run.sh --execute
```

The script exits non-zero and prints `BLOCKED: <reason>` if any criterion is
unmet.  It prints `SAFE to archive` only when all checks pass.

---

## 7. Rollback Plan

The archival is a pure `git mv` operation — no content is deleted.  If the
archival PR merges and an immediate rollback is needed:

1. Open a new PR from a branch based on `main`.
2. Reverse every `git mv` from §3:
   - `legacy/zig/src/` → `src/`
   - `legacy/zig/build.zig` → `build.zig`
   - `legacy/zig/build.zig.zon` → `build.zig.zon`
   - `legacy/zig/.zigversion` → `.zigversion`
   - `legacy/zig/.github-workflows/ci.yml` → `.github/workflows/ci.yml`
3. Revert any SCAN_PATHS / README changes from §5.
4. Merge and re-tag if necessary.

Because `git mv` preserves history, `git log --follow legacy/zig/src/main.zig`
(or the reversed path) will show the full commit history regardless of
direction.
