# WP-M0-08: FS stores with the `.mkit` on-disk layout (`mkit-server` `fs` feature)

- **Milestone/track:** M0
- **Base:** `feat/mkit-server`; **branch:** `mkit-server/wp-m0-08-fs-stores`
- **Depends on:** M0-03, M0-04
- **Size:** M (~700–1000 lines)
- **Open-question dependency:** overview Q3 (the `fs` feature lives in `mkit-server`, not `-native`) and Q4 (refs as
  files, no replay/quota). Build per the defaults unless the user overrides them.

## Conventions

Same as WP-M0-01: TMPDIR, trailer, no CI polling, no proto change, a size check, workspace lints.

## Goal

Provide the two stores that let `mkit serve <repo-path>` (ssh; std-only, no async runtime) and `mkit-server --repo-root` keep using
the exact on-disk layout `FileTransport` uses today:

- `FsBlobStore`: streaming content-addressed writes to `<root>/packs/<64-hex>`, with BLAKE3 verified before a
  temp → fsync → rename publish
- `FsLayoutStore`: refs as files under `<root>/refs/...`, CAS serialized by the same `<root>/.mkit/refs/.lock` file
  lock. It **delegates** to `mkit_transport_file::FileTransport`, so the semantics stay byte-identical.

Both are std-only (no tokio) and pass the storage-trait suite with the capabilities they declare.

## PRD refs

§5.1 ("FS blobs (keeping the `.mkit` on-disk layout)"), §5.3 (BlobStore rules), §6.9 ("The FS backend keeps the
`.mkit` layout, so `mkit serve <repo-path>` integrations keep working"), D2, D23.

## Scope

**IN:** `src/fs/{mod.rs, blob.rs, layout.rs}` behind feature `fs = ["dep:mkit-transport-file"]`
(`cfg(not(target_arch = "wasm32"))`); storage-suite runs; layout interop tests.

**OUT:** SQLite metadata (M0-09); async offloading (`-native` wraps these in `spawn_blocking` in M0-10); GC of stale
temp files beyond what `FileTransport` does; replay/quota on FS (unsupported by design).

## Files

- `rust/crates/mkit-server/Cargo.toml`: `mkit-transport-file = { version = "0.4", path = "../mkit-transport-file", optional = true }`;
  feature `fs`; dev-deps `tempfile`, and `mkit-server-conformance` (path) for the suite macro. **Check for a
  dev-dep cycle:** `mkit-server-conformance` depends on `mkit-server`. A dev-dep cycle is allowed by Cargo, but if it
  causes trouble, put the suite run in `rust/crates/mkit-server-conformance/tests/fs_backends.rs` instead (preferred).
- `src/fs/blob.rs`: `FsBlobStore { root: PathBuf, keyspace: &'static str /* default "packs" */ }`
  (`FsBlobStore::new(root)` = keyspace `packs`; `with_keyspace(root, "objects")` for M4's object CAS, R-07)
  - `begin`: create `<root>/packs/` (0700 best-effort, like `RefLock::acquire`, `mkit-transport-file/src/lib.rs:210-236`)
    and a temp file `<root>/packs/.<hex>.tmp.<pid>.<seq>` (same naming as `write_atomic`, `lib.rs:62-97`)
  - `PackSink::write`: append plus incremental `mkit_core::hash::Hasher`
  - `commit`: length check, BLAKE3 == key, `fsync` file, `rename` over the destination (idempotent for identical
    bytes), `fsync` parent dir (`sync_parent`, `lib.rs:163-178`). Return `AlreadyPresent` if the destination
    existed before the rename.
  - `abort` and `Drop`: remove the temp file
  - `get`: open and return `BlobBody::Stream` reading 64 KiB blocks (or `Bytes` for files ≤ 1 MiB); a range via
    seek+take
  - `head`: `metadata().len()`
  - `probe`: `root` is a dir
  - `delete`: `remove_file`, then `sync_parent`; `NotFound` → `Ok(false)` (R-06; unused until M5)
- `src/fs/layout.rs`: `FsLayoutStore { tx: FileTransport, root: PathBuf }`, implementing the M0-02a key-level
  `NamespaceStore` for the **refs key class only** (`"r" 00 <repo> 00 <refname>`, M0-02a `store/keys.rs`):
  - `capabilities() = { atomic_multi_key: false, key_classes: RefsOnly, membership: StorePresence,
    implicit_layout_version: Some(1) }`: the store can't hold the `v` layout-version key, so its version is the
    `.mkit` on-disk format's and planners never send `v` here (review 01 nit, R-82)
  - `get(r-key)` → `tx.read_ref` (`lib.rs:458-471`, which keeps the symlink-escape guard); any other key class →
    `Unsupported`. The single-repo `<repo>` component must equal the configured repo (multi-repo directories are
    WP-1.15).
  - `scan` over the refs range: call `tx.list_refs("")` then filter to `[start, end)` and after the cursor. That
    returns names relative to `<root>`, which are full `refs/...` names because refs live at `<root>/refs/...`.
    Confirm with a test. Sort by key bytes and paginate in memory; the cursor is the last key.
  - `apply` (single writer via the ref lock; M0-02a rule 4 holds because `FileTransport::update_ref` is one
    synchronous lock-write-rename step):
    - more than one write, or a precondition on a different key than the write → `Unsupported` (the pipeline issues
      sequential single-key batches for non-atomic stores)
    - `Put(k, v)` with no precondition → `update_ref(Any)`; with `Absent(k)` → `Missing`; with `Equals(k, old)` →
      `Match(old)`; `Present(k)` alone → `Unsupported`
    - `RefConflict` → `BatchOutcome::PreconditionFailed { index: 0, observed: tx.read_ref(..) }`, read back like
      `cas_conflict_body` (`serve/mod.rs:637-655`)
    - `Delete(k)` → `Unsupported` in M0 (there is no delete verb today; WP-1.10 adds ref deletion)
    - `NotAfter(d)` (R-61) is accepted next to the single key precondition: read the system clock in the same
      synchronous step as the write, under the ref lock when the lock helper is available (otherwise immediately
      before `update_ref`, with no await in between); `now > d` → `PreconditionFailed { index, observed:
      be64(now) }` and nothing written
  - `probe` → `tx.list_refs("")` is Ok (the same cheap probe as `mkit-transport-connect/src/health.rs:40-55`)

  Forward note (reconciliation R-13): `FsLayoutStore` is the **permanent** metadata store of the ssh path, because
  the default `mkit` CLI must stay server-free (no SQLite). Later WPs extend it with files under the served root,
  read and written under the same `.mkit/refs/.lock`: per-repo directories for multi-repo addressing (WP-1.15),
  the namespace grant epoch and registered ssh grants (WP-2.12, which makes `grant_epoch` preconditions supported
  here). Keep the lock helper reusable for that.
- `rust/crates/mkit-server-conformance/tests/fs_backends.rs`:
  `storage_suite!(fs, blob = || FsBlobStore::new(tempdir()), kv = || FsLayoutStore::new(tempdir()), reopen = |dir| FsLayoutStore::new(dir))`
  (content-index cases skip: `RefsOnly`)

## Design

```rust
#[cfg(all(feature = "fs", not(target_arch = "wasm32")))]
pub mod fs {
    pub struct FsBlobStore { /* root */ }
    impl FsBlobStore { pub fn new(root: impl Into<PathBuf>) -> Self; }
    pub struct FsPackSink { /* tmp path, file, hasher, written, declared, key, dest */ }
    pub struct FsLayoutStore { /* FileTransport, root */ }
    impl FsLayoutStore { pub fn new(root: impl Into<PathBuf>) -> Self; }
}
```

All methods are `async fn` bodies doing blocking `std::fs` I/O. That's correct under the CLI's `block_on` (M0-13).
M0-10 wraps them in `spawn_blocking` for the tokio server.

## Acceptance criteria

- [ ] `fs` compiles without tokio in `mkit-server`'s own graph (the `cargo tree` check above prints `ok`).
- [ ] The storage suite passes for `FsBlobStore` (all blob cases) and `FsLayoutStore` (refs-class kv cases,
      durability via `reopen`, and correct `Unsupported` behavior).
- [ ] Both interop tests pass, proving the on-disk layout is unchanged.
- [ ] No duplicated CAS/lock code: `FsLayoutStore` delegates to `FileTransport`.
- [ ] Temp files never survive a failed commit.
- [ ] A backend test (not the black-box suite, which cannot see it) proves `FsLayoutStore` reads the `NotAfter` clock inside
      the locked check-and-write step, never before taking the lock (rule 8).

## Risks / gotchas

- `FileTransport::list_refs(prefix)` returns names **relative to the prefix directory** (`lib.rs:473-495`,
  `collect_refs(&dir, &dir, ..)`). Listing from `""` and filtering avoids the ambiguity; test it.
- `FileTransport::upload_pack` writes whole buffers. Don't route blobs through it; `FsBlobStore` is the streaming
  path. Both use `<root>/packs/<hex>`.
- macOS `/tmp` is a symlink. The escape guard canonicalizes lazily (`lib.rs:318-327`), and tests must use the TMPDIR
  from the conventions.
- The `.mkit` dir must exist for the lock (`RepoLayout::single(root).refs_dir()`); `FileTransport` creates it on
  demand.
