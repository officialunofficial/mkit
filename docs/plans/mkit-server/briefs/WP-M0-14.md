# WP-M0-14: Encrypted-stream listener moves into the `mkit-server` binary

- **Milestone/track:** M0
- **Base:** `feat/mkit-server`; **branch:** `mkit-server/wp-m0-14-enc-listener`
- **Depends on:** M0-10, M0-12
- **Size:** M (~800–1000 lines incl. moved tests)

## Conventions

Same as WP-M0-01: TMPDIR, trailer, no CI polling, no proto change, a size check, workspace lints.

## Goal

Host the `mkit+enc://` listener in `mkit-server serve` (D31: the long-running listeners live in the server binary),
running each encrypted session through the M0-12 ssh-frame session over the pipeline. It keeps every fail-closed
rule, timeout and budget of today's `mkit serve --listen-enc`. The CLI copy stays in this WP; M0-15 removes it.

## PRD refs

§5.1 (`-native` "hosts the long-running HTTP and enc listeners"), §6.9, D23, D31. `docs/specs/SPEC-TRANSPORT-ENC.md`
§6 (listener, fail-closed, identity key, idle and handshake timeouts).

## Scope

**IN:**
- `mkit-transport-enc`: an **additive** async listener API with an external listener and a shutdown future
- `mkit-server-native` `enc` feature with `src/enc.rs`: config and fail-closed gate, peer allowlist loader, server key
  load or create, and the `EncFrameSource`/`EncFrameSink` adapters
- `serve` flags; the moved tests
- the `nextest.toml` ignored-lane filter kept consistent

**OUT:** removing `--listen-enc` from the CLI (M0-15); changing the enc wire or handshake.

## Acceptance criteria

- [ ] `mkit-server serve --listen-enc` behaves like `mkit serve --listen-enc`: fail-closed gate, messages, banner,
      timeouts, budgets and server_id prefix.
- [ ] Every enc session runs through `mkit_server::ssh::serve_session` on the shared pipeline.
- [ ] `mkit-transport-enc`'s change is additive, and its existing tests pass unchanged.
- [ ] Graceful shutdown covers the enc listener.
- [ ] No `unsafe` added to `mkit-server-native` (it stays at geiger 0 if added to the scan).
- [ ] The ignored lane still selects the moved tests (verify with `cargo nextest list --profile ignored-lane --run-ignored ignored-only | grep listen_enc`).

## Risks / gotchas

- `serve_tcp_*` today builds its own tokio runtime. Inside `mkit-server` you're already on a runtime; use only the
  new async entry point, never the blocking one, to avoid a nested-runtime panic.
- The enc session is async on tokio worker threads. `Blocking<S>` store wrappers (M0-09) keep the FS I/O off the
  workers. Today's CLI code calls sync `FileTransport` inside async (`enc.rs:378`); don't replicate that.
