## Conventions

Same as WP-M0-01: TMPDIR, trailer, no CI polling, no proto change, a size check, workspace lints. Workers-specific:
worker-touching code is `#[cfg(target_arch = "wasm32")]`, and pure logic stays host-testable, following the

## Goal

Create the workers-rs adapter crate's **storage half**:

- an R2 `BlobStore` that **streams** in both directions (no whole-pack buffering; reconciliation R-25)
- a `SqlConn` over Durable Object SQLite (`sql().exec` + `transactionSync`), so each DO runs the **same**
  `SqlKvStore` code as native (M0-09)
- the DO-side request handler for the key-level contract (M0-02a)
- a Worker-side `NamespaceStore` client that routes each `Partition` to its own DO instance

The design is partition-routed from day one (D34: coordinator, ref shards, index shards; D21 is superseded). M0
wiring has one partition (`Partition::Namespace`, the `"root"` DO), and the wire is unchanged.

## Durable Object constraints this WP designs for (Cloudflare docs, 2026-09; reconciliation R-26)

- ~1,000 req/s pass-through per DO and ~200–500 req/s for storage-writing requests: keep DO calls per RPC to ~2
  (`get_many` + `apply`) and never call the DO for blob bytes.
- 128 MB memory shared by every DO and request in an isolate, and wasm memory never shrinks: no whole-pack buffers
  anywhere; per-request memory bounded by one chunk (≤ 1 MiB).
- SQLite: 2 MB rows, 100 bound parameters, 100 KB statements (M0-09 respects these; `MAX_VALUE_BYTES` = 1 MiB).
- 10,000 subrequests per invocation (Workers Paid) and at most 6 connections per invocation **simultaneously waiting
  for response headers** (a 7th queues until one gets its headers; open connections past the header phase don't
  count; Cloudflare relaxed this on 2026-04-09, https://developers.cloudflare.com/workers/platform/limits/): the
  adapter never has more than 4 subrequests per request in flight at once, which also keeps headroom for R2.
- One alarm per DO, at-least-once, 6 retries, 15 min wall; CPU 30 s default (configurable to 5 min): no alarms in
  M0 (the timers layout is reserved in M0-02a; WP-1.24 runs them).
- A DO is pinned near its first access and supports `locationHint`/jurisdiction: the partition → stub function
  takes an optional `Placement { location_hint, jurisdiction }`, default none (M0 passes none; WP-1.8 exposes it as
  a namespace-creation config option).
- PITR is 30 days and per DO only: the DO handler exposes the portable M0-02b export (`NsCall::Export`), so WP-1.29
  can run a periodic app-level dump to R2.
- Storage cap: 10 GB per SQLite-backed DO on Workers Paid (1 GB on Free). At the cap, writes fail with `SQLITE_FULL`
  while reads and `DELETE` keep working (https://developers.cloudflare.com/durable-objects/platform/limits/):
  `DoSqlConn` maps that error to `SqlError::Full` → `StoreError::Full` (fail closed, 00-plan P-24; WP-1.29 alerts).
- DO bindings are always local in `wrangler dev`: `wrangler dev` conformance can't prove placement, limits or
  PITR; deployed staging (M1+) must run the same suites.

- `src/r2.rs`: `R2BlobStore { env: worker::Env, binding: &'static str /*"STORAGE"*/, keyspace: &'static str /*"packs"*/, max_bytes: u64 }`
  - **streaming put** (R-25): `begin` opens a `FixedLengthStream` of the declared length fed by a bounded channel,
    builds `bucket.put(key, stream).only_if(Conditional{ etag_does_not_match: Some("*") })` (the conditional of
    `put_addressed`, `service.rs:96-113`), and **spawns its `execute()` future with
    `wasm_bindgen_futures::spawn_local`, keeping a `futures::channel::oneshot` for the result** (review 01, R-67).
    `PutOptionsBuilder::execute` is an `async fn` (workers-rs 0.8.6 `r2/builder.rs:234`): the JS put doesn't start
    until it is polled, so a sink that writes into the bounded channel while the put future sits unpolled until
    `commit` would deadlock on the first full channel. `write` hashes each chunk incrementally and sends it, **except
    that the final chunk is withheld until BLAKE3(all bytes) == key and the length matches**; `commit` sends the
    final chunk, closes the stream and awaits the oneshot (a 412 → `AlreadyPresent`); on mismatch or `abort` the
    stream is errored and the oneshot awaited, the put fails, and nothing becomes visible. Memory is bounded by one
    chunk plus the channel depth (1).
  - `max_bytes` (64 MiB default) is kept only as a **documented stopgap** request-size cap until M1 parts land; it
    is a counter, not a buffer
  - a 412 from the conditional → `AlreadyPresent`
  - key `<keyspace>/<hex>` (`service.rs:92-94` shape for `packs`)
  - `get`: optional range → `BlobBody::Stream` over the R2 object body (never `bytes()` on the whole object)
  - `head` → `bucket.head`; `delete` → `bucket.delete` (R-06; unused until M5)
  - `probe` → `mkit_worker_common::health::r2_head_probe`
  - map errors through `mkit_server::storage_error::describe_and_map` + `worker::console_error!` (issue #794 pattern)
- `src/do_sql.rs`: `DoSqlConn { state: Rc<worker::State>, storage: JsValue }` implementing
  `mkit_server::sql::SqlConn`:
  - `exec`/`query` via `state.storage().sql().exec(sql, bindings)`, mapping `SqlValue`↔`JsValue` (Blob ↔
    `Uint8Array`; Integer ↔ f64/BigInt: check workers-rs's `SqlStorageValue` i64 support and reject values outside
    ±2^53 when converting through f64)
  - `transaction` via `storage.transactionSync(closure)`: M0-09's signature takes an owned
    `Box<dyn FnOnce(Self) -> Result<T, SqlError> + 'static>` (R-68), so wrap it with `Closure::once` over a clone of
    the `DoSqlConn` handle and return the result through an `Rc<RefCell<Option<Result<T, SqlError>>>>`; no `unsafe`.
    Port `apps/mkit-worker-common/src/replay.rs:62-109`, and **reuse** it if `mkit-worker-common` can expose the
    bridge without the ledger (a small additive `pub fn transaction_sync` there; allowed because it doesn't change
    the demo workers' behavior)
  - `now_ms` → `worker::Date::now()` inside the DO (the DO's own clock, which advances with I/O, so it reflects the
    request's arrival at the DO); this is the clock `NotAfter` uses (M0-02a rule 8)
  - errors: an exception whose message contains `SQLITE_FULL` → `SqlError::Full`
- `src/ns_object.rs`: `pub async fn handle(state: &worker::State, conn: &DoSqlConn, req: worker::Request) -> worker::Result<worker::Response>`:
  decode `wire::NsCall` (JSON), run `mkit_server::sql::migrate` once per DO instance (a `Cell<bool>`), dispatch to
  `SqlKvStore<DoSqlConn>` (whose `stats` uses `storage.sql.databaseSize`), return `wire::NsReply` JSON. The DO is a pure key-level store: no pipeline logic runs in
  it, which keeps it replaceable by any other backend.
- `src/ns_client.rs`: `DoNamespaceStore { env, binding: &'static str /*"REFSTORE"*/, placement: Placement }`
  implementing `NamespaceStore`: each method POSTs `https://ns/<op>` to
  `env.durable_object(binding)?.id_from_name(&naming::do_name(p))?.get_stub()?` (pattern `service.rs:118-155`);
  errors redacted; 4xx/5xx from the DO → `StoreError::Unavailable`, except typed `NsReply::Err { kind }`;
  `capabilities()` = `{ atomic_multi_key: true, key_classes: All, membership: StorePresence }`.
- `src/naming.rs` (host-testable): `do_target(p: &Partition) -> (binding, name)`. M0: `Partition::Namespace(default)`
  → (`REFSTORE`, `"root"`) (Q13, matching `REFSTORE_INSTANCE`, `service.rs:66`). Reserved for D34 (WP-1.8 adds the
  bindings; R-29): `Coordinator` → (`NS_COORD`, `c:<ns>`), `Ref` → (`REF_SHARD`, `r:<ns>\n<repo>\n<shard_ref>`),
  `RepoIndex` → (`REPO_INDEX`, `i:<ns>\n<repo>\n<prefix>`), `RefIndex` → (`REPO_INDEX`, `x:<ns>\n<repo>\n<bucket>`),
  `ContentShard` → (`CONTENT_INDEX`, `ci:<shard:03x>`). One DO class per shard kind.
- `src/wire.rs` (host-testable): `enum NsCall { Get{key}, GetMany{keys}, Scan{start, end, after, limit}, Apply{batch}, Stats, Probe, Export{after, limit} }`,
  `enum NsReply { … , Err { kind: NsErrKind, message: String } }` with `NsErrKind::Full` among the kinds. The
  partition is implied by the DO instance. The batch encoding carries every precondition kind, including
  `NotAfter(deadline_ms)` as an integer (checked by the DO against its own clock, never by the Worker).

## Acceptance criteria

- [ ] The crate builds and passes clippy for wasm32 and the host. The wasm dep-graph check covers it and passes.
- [ ] `SqlKvStore` runs unmodified over `DoSqlConn`. No SQL is duplicated in this crate; no pipeline logic runs in the DO.
- [ ] R2 puts and gets stream: no code path holds a whole pack in memory. A put becomes visible only if BLAKE3
      verification passes (withheld final chunk) and is conditional. The 64 MiB cap is documented as an M1 stopgap.
- [ ] The partition → DO routing function exists and is tested (namespaces and content shards). The M0 default maps
      to `"root"`. `Placement` exists and defaults to none.
- [ ] Fault hooks exist behind `test-faults` only.
- [ ] Nothing in `apps/` except an optional additive `mkit-worker-common` helper changes. The demo workers are
      unaffected (their CI steps pass).
- [ ] The R2 put is `spawn_local`'d at `begin` and awaited at `commit`/`abort`; no deadlock with a depth-1 channel.
- [ ] `NotAfter` is evaluated inside the DO with the DO's clock; `SQLITE_FULL` maps to `StoreError::Full`.
- [ ] The wasm-bindgen move is minimal and the `web` gate passes (mkit-wasm builds, bundler glue patch applies).

## Risks / gotchas

- `#[durable_object]` must stay in the final cdylib (`apps/vcs-worker`); this crate exposes plain functions. Don't
  put the macro here (export and linking of wasm-bindgen classes from a dependency is fragile).
- DO `exec` returns a cursor. Materialize rows before returning, and never hold a cursor across `transactionSync`
  boundaries.
- `worker` handles are `!Send`. Every async fn body that touches them is wasm-only. The generic pipeline sees
  `MaybeSend` (no bound on wasm), so no `SendFuture` is needed inside the stores. The single `send_wrap` sits in the
  Connect handler (M0-06).
- Adding `mkit-worker-common` (which declares `[workspace]`) as a path dependency of a `rust/` member: Cargo ignores
  a dependency's `[workspace]` table. Verify that `cargo metadata` in `rust/` doesn't list it as a member.
- `rust/Cargo.lock` gains workers-rs and wasm-bindgen crates. `cargo deny` must pass (the same crates are already
  vetted in `apps/*/Cargo.lock`).
- **wasm-bindgen bump (review 01, R-80).** `worker` 0.8.6 requires `wasm-bindgen >= 0.2.128`, and `rust/Cargo.lock`
  pins 0.2.127 today (`apps/vcs-worker/Cargo.lock` already has 0.2.128). Adding this crate moves the whole `rust/`
  workspace, **including `mkit-wasm`**, to ≥ 0.2.128 (plus matching `js-sys`/`web-sys`/`wasm-bindgen-futures`).
  `wasm-pack` 0.13.1 fetches the matching `wasm-bindgen-cli`, but the generated JS glue can change shape: run the
  `web` gate above (the bundler-glue patcher fails loudly if the glue changed) and call the bump out in the PR body.
  The `rust/Cargo.lock` change also triggers `web.yml` in CI. Don't bump further than `worker` requires.
