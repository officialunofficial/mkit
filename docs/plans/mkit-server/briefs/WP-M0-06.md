# WP-M0-06: `connect` feature: `mkit.transport.v1` `TransportService` + health over the pipeline

- **Milestone/track:** M0
- **Base:** `feat/mkit-server`; **branch:** `mkit-server/wp-m0-06-connect-binding`
- **Depends on:** M0-05b (the full pipeline incl. `UploadSession`/`DownloadStream`; review 01 split M0-05, R-72)
- **Size:** M (~700–900 hand-written lines, plus ~vendored `generated/`, which doesn't count)

## Conventions

Same as WP-M0-01: TMPDIR, trailer, no CI polling, no proto change, a size check, workspace lints.

## Goal

Give `mkit-server` a wasm-clean Connect binding, the `connect` cargo feature (default on). It provides:

- vendored codegen for `proto/mkit/transport/v1/transport.proto` + `proto/grpc/health/v1/health.proto`
- a `TransportService` implementation that delegates every RPC to `Pipeline`
- a Connect `Interceptor` that runs pipeline stage 0 with access to the exact request bytes
- a `grpc.health.v1.Health` implementation
- a `router(pipeline)` constructor

Both `mkit-server-native` (M0-10) and `mkit-server-worker` (M0-17) mount it unchanged.

## PRD refs

§5.1 (`mkit-server` features: `connect` default on), §5.2 (SendFuture once per handler), §8 M0 ("no wire change"),
D1, D24. Overview finding 2 (connectrpc without `server` works on wasm).

  - `intercept_streaming`: the same with `unary_body: None`

- `src/connect/service.rs`: `ConnectTransport<B, N, H>` implementing the generated `TransportService`. Each method:
  1. take `Authenticated` from `ctx.extensions()` (missing → `unauthenticated("missing authorization")`, matching
     vcs-worker `service.rs:572-577`)
  2. decode fields with the M0-04 helpers (`refs::condition_from_wire`, `refs::hash_from_slice`, `validate_ref_*`)
  3. call the pipeline inside `crate::rt::send_wrap(async move { … })`
  4. encode the response

  `UploadPack`: first message must be `header`, then `session.push` per chunk, then `finish`. `DownloadPack`:
  `Response::stream_ok(stream)`, header message then chunk messages. `UpdateRef` conflict →
  `failed_precondition`, `AdvanceRefs` conflicts → typed `AdvanceOutcome` (never an error).
- `src/connect/health.rs`: implements the generated `Health`:
  - `check("")` or `check("mkit.transport.v1.TransportService")` → `pipeline.health()` → `SERVING`/`NOT_SERVING`

  - `Watch` → `unimplemented`, like `apps/vcs-worker/src/worker_impl/health.rs`

- `src/connect/error.rs`: `impl From<ServerError> for connectrpc::ConnectError`, a total map from `Code` (`Aborted` →

  message is `public_message()` only. It also carries the response shaping from M0-01 (reconciliation R-03):
  `http_status()` → `ConnectError::with_http_status`, `headers()` → `with_headers` (an `http::HeaderMap`, invalid
  names/values dropped with a `tracing::warn!`), `details()` → `with_detail` (connectrpc 0.9 `error.rs:321, 385, 488`).
  This is the single error-mapping table for Connect (A14); handlers never build `ConnectError` directly. Also
  `fn from_upload_error`.
- `test-faults` (feature forwarded to the pipeline): the interceptor parses `TestDirectives` from

## Design

```rust
pub fn router<B, N, H>(pipeline: Arc<Pipeline<B, N, H>>) -> connectrpc::Router
where B: BlobStore + 'static, N: NamespaceStore + 'static, H: HookSet + 'static;
pub fn service<B, N, H>(pipeline: Arc<Pipeline<B, N, H>>) -> connectrpc::ConnectRpcService;  // router + AuthInterceptor
```

`Arc<Pipeline>` must be `Send + Sync` on native. On wasm it's `!Send`, which is fine: every handler body goes
through `send_wrap`, and the interceptor's `async_trait` futures need `Send` too. Check how `connectrpc::async_trait`
bounds futures on wasm. If they require `Send`, wrap the interceptor body in `send_wrap` as well.

## Risks / gotchas

- The generated trait requires `+ Send` handler futures. Wrap each handler body in `send_wrap` once (PRD §5.2).
  Don't sprinkle `SendFuture` around individual awaits.
- Deadline headers: parsing `connect-timeout-ms` calls `Instant::now()`, which panics on wasm. That's filtered by the
  Workers adapter (`mkit_worker_common::adapter::is_deadline_header`), not here, but note it in the module docs.
- `ServiceRequest` views borrow the request. Convert to owned values before any `.await` that crosses into
  `send_wrap`. See `vcs-worker/src/worker_impl/service.rs:188-194` for the `to_owned_message()` pattern.
- There are now three vendored copies of the transport codegen until M0-17 deletes vcs-worker's. The regen script
  must refresh all three consistently.
