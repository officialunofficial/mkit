## Conventions

Same as WP-M0-01: TMPDIR, trailer, no CI polling, no proto change, a size check, workspace lints.

## Goal

Ship the long-running native server (D31):

- an embeddable axum router builder, with production tower layers (timeouts, concurrency cap, body limit, tracing
  with header redaction, CORS)
- graceful shutdown
- the `mkit-server` binary, configured for FS or SQLite storage and none, bearer or auth-v2 auth

It must pass the black-box wire suite in-process for FS+SQLite. It must also reproduce the removed `mkit serve --http`
behavior (fail-closed bearer gate, shared `serve.lock`, Ctrl-C drain) so M0-15 can delete the CLI path.

The fail-closed rules copy `serve/http.rs:46-86` **exactly**:
- a token together with the unsafe flag → usage error
- an empty token → config error
- neither → refuse to bind with the same guidance text, adapted to the new flag names
- the unsafe flag prints the same loud warning banner

`--auth auth-v2` without `--meta sqlite:` → config error (Q4).

**No split brain between SQLite refs and file refs (R-81).** With `--meta sqlite:`, refs live in SQLite, while
`mkit serve` (ssh) and local `mkit` commands on the same root read and write file refs (`FsLayoutStore` /
`FileTransport`). Serving both from one root would silently diverge, so the binary **refuses** the combination:
- At startup with `--meta sqlite:`, if the repo root's file-ref layout is in use (any ref file under the
  `FsLayoutStore` ref directory, i.e. `FileTransport::list_refs("")` is non-empty), exit with `CONFIG_ERROR` and:
  "repo root <DIR> already holds file-based refs (used by 'mkit serve' and local mkit commands); --meta sqlite
  would keep a second, diverging copy of the refs. Serve this root with --meta fs-layout, or point --repo-root at a
  root without file refs."
- Otherwise it writes a marker `<root>/.mkit/server-meta` containing `sqlite` (created with `create_new`, fsynced)
  before binding, and `FsLayoutStore::open` (M0-08's `mkit_server::fs` module; this WP adds the check there) refuses a
  root carrying the marker with the mirror-image message, so a later `mkit serve` or `--meta fs-layout` on that root
  fails closed too. The marker is never removed automatically; the README documents removing it by hand after
  migrating refs back to files. `--repo-root` must contain `.mkit`, the same check as
`resolve_repo_path`, `serve/mod.rs:220-235`, including the `MKIT_SERVE_ROOT` containment env. Hold
`mkit_core::repo_lock::acquire_shared(&repo_root.join(".mkit"), "serve.lock", DEFAULT_TIMEOUT)` for the process
lifetime (`serve/mod.rs:164-174`; the constant is `mkit-cli/src/commands/mod.rs:347`, so duplicate the literal
`"serve.lock"` or move the constant to `mkit_core::repo_lock` in this PR). Exit codes follow `mkit-cli`'s `exit`
module values (USAGE, CONFIG_ERROR, UNAVAILABLE). Copy the numeric values and document them.

Storage wiring:
- blobs: `Blocking<FsBlobStore>(repo_root)`
- meta: `Blocking<FsLayoutStore>(repo_root)` for `fs-layout`, or `Blocking<SqlKvStore<RusqliteConn>>` for sqlite
  (M0-09; `ContentIndex` over the same store exists but is unused in M0)
- `PipelineConfig`:
  - `addressing: Single { repo: RepoId::single(--repository or "default") }`
  - `upload_limits: { max_total_bytes: --max-pack-bytes or PACK_BODY_LIMIT, max_chunks: u32::MAX }`
  - `write_quota: Some(DEFAULT_WRITE_QUOTA)` for auth-v2, else `None`

- [ ] `wire_fs_layout_bearer` matches the legacy `mkit serve --http` baseline case for case.
- [ ] Fail-closed auth semantics and messages match `serve/http.rs`. The unsafe banner is present.

- [ ] `build_router` is `pub` and documented as mountable. The README has an operator section.
- [ ] `mkit-server-native` stays `publish = false` during the epic; WP-REL makes it publishable at the final

## Risks / gotchas

- axum 0.8 + connectrpc 0.9 `ConnectRpcService` as a fallback service: follow `serve/http.rs:164-172` exactly.
  The `.with_interceptor` chaining is done inside `mkit_server::connect::service`.
- Timeouts on streaming RPCs: a global `TimeoutLayer` kills long uploads. Select by path.
- `SetSensitiveRequestHeaders` must run **before** `TraceLayer` records headers (outer layer).
- `spawn_blocking` pool exhaustion: `Blocking<S>` is fine for M0. Note in the README that `max_concurrency` should
  stay below tokio's blocking-pool size (default 512).
- Don't start the enc listener here. M0-14 adds it to the same `serve` command.
