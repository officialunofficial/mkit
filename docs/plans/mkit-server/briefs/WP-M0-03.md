## Goal

Create `rust/crates/mkit-server-conformance` and its part (a) from PRD §5.1: a reusable, generic storage-trait
suite. Every backend (memory now; FS, SQLite, S3 and, via the shared SQL code, the DO logic later) runs the suite
with one macro invocation. Wire it up against the M0-02a memory implementations.

## PRD refs

§5.1 (`mkit-server-conformance` row), §5.3 "Custom backends must provide … The conformance suite is the gate", D1, D2.

## Scope

**IN:** the crate scaffold (native only, `publish = false`); the `storage` module with async case functions for the
M0-02a key-level `NamespaceStore` contract (including the `NotAfter` commit deadline), `BlobStore` and the M0-02b
`ContentIndex` layer; crash/restart and
cancellation cases (reconciliation R-22); export/import round trip; a `storage_suite!` macro that expands one
`#[tokio::test]` per case; capability-gated skipping; the suite run against `MemoryKv`/`MemoryBlobStore`.

**OUT:** the black-box wire suite (M0-07), backend-specific tests, fake S3 (M0-11). Replay/quota/CAS *semantics*
are planner behavior (M0-05a/05b) and are proven per backend by the wire suite over that backend (M0-10, M0-11, M0-17);
this suite proves the key-level contract they rely on.

## Design

```rust
#[derive(Debug)] pub enum CaseResult { Pass, Skip(&'static str) }
pub type CaseFn<S> = fn(S) -> crate::rt::BoxFuture<'static, Result<CaseResult, String>>;

pub fn blob_cases<B: BlobStore + 'static>() -> Vec<(&'static str, CaseFn<B>)>;
pub fn kv_cases<N: NamespaceStore + 'static>() -> Vec<(&'static str, CaseFn<N>)>;
pub fn content_index_cases<N: NamespaceStore + 'static>() -> Vec<(&'static str, CaseFn<N>)>;   // via ContentIndex<N>

/// Durability cases need to reopen the same backend from its persistent location. Backends without persistence
/// (memory) supply `reopen = None` and those cases skip with a reason.
pub trait Reopen<N>: Fn(&std::path::Path) -> N {}

/// Clock control for the `NotAfter` cases (R-61), passed to the macro as `clock = ..`. A backend whose store clock
/// can be injected passes `StoreClock::Injectable(|c| MemoryKv::with_clock(c))`-style factories and gets the full deadline cases; a backend
/// whose clock can't be injected (a Durable Object under `wrangler dev`, a remote KV) runs only the cases that use
/// deadlines far in the past or future relative to the real clock.
pub enum StoreClock<N> { Injectable(fn(ManualClock) -> N), RealOnly }

/// Expands to one #[tokio::test(flavor = "multi_thread")] per case, named `<prefix>__<case>`, so nextest output
/// names the failing case. Each test builds a fresh backend via the factory (and a temp dir when `reopen` is given).
#[macro_export] macro_rules! storage_suite { /* blob = .., kv = .., reopen = .. */ }
```

Cases. Each is small and deterministic; no wall-clock sleeps.

- **BlobStore:** `blob.roundtrip`, `blob.zero_length`, `blob.hash_mismatch_rejected_nothing_visible`,
  `blob.len_short_rejected`, `blob.len_long_rejected`, `blob.abort_leaves_nothing`,
  `blob.identical_reput_already_present`, `blob.concurrent_same_key_both_succeed`, `blob.get_missing_none`,
  `blob.head_len`, `blob.range_first_middle_last`, `blob.multi_chunk_write_order`, `blob.probe_ok`,
  `blob.delete_then_get_none` (R-06), `blob.get_large_is_streamed` (a 5 MiB blob comes back as `BlobBody::Stream`
  or in ≤ 1 MiB pieces; R-25)
- **Key-level contract (`kv.*`):**
  - `kv.get_missing_none`, `kv.put_then_get`, `kv.delete_then_get_none`, `kv.has_matches_get`,
    `kv.get_many_order_and_missing`
  - Preconditions: `kv.absent_ok_and_fail`, `kv.present_ok_and_fail`, `kv.equals_ok_and_fail_reports_observed`,
    `kv.first_failing_precondition_index`, `kv.failed_batch_writes_nothing` (multi-write batch)
  - Scan: `kv.scan_byte_order` (keys with 0x00, 0xff, prefixes of each other), `kv.scan_bounds_half_open`,
    `kv.scan_cursor_resumes_strictly_after`, `kv.scan_pagination_stable_under_concurrent_puts_after_cursor`,
    `kv.scan_limit_respected`
  - Limits: `kv.oversize_key_invalid`, `kv.oversize_value_invalid` (nothing written)
  - Isolation: `kv.partitions_isolated` (two namespaces and a content shard, same keys)
  - Concurrency: `kv.concurrent_absent_single_winner` (16 tasks race `Absent(k)+Put(k)`; exactly one `Committed`);
    must pass on a single-writer backend too (no assumption of parallel applies)
  - Capabilities: `kv.refs_only_rejects_other_classes` (KeyClasses::RefsOnly → `Unsupported`, nothing written),
    `kv.non_atomic_rejects_multi_write_batch`
  - `kv.layout_version_key_roundtrip` (skips with a reason on stores that report `implicit_layout_version`, which
    never hold the `v` key), `kv.refs_only_reports_implicit_layout_version`, `kv.probe_ok`
  - Class isolation: `kv.class_tags_are_zero_terminated` (keys of `o`/`oq`/`os`/`oc`, `p`/`px`/`pp`, `t`/`tb`,
    `e`/`el` written together; a scan of each class returns exactly its own keys)
  - **Commit deadline (`NotAfter`, R-61):**
    - `kv.not_after_past_deadline_fails_writing_nothing` (real clock: deadline = now − 60 s → `PreconditionFailed` at
      the `NotAfter` index, `observed` = 8 bytes, nothing written) — every backend
    - `kv.not_after_future_deadline_commits` (deadline = now + 60 s) — every backend
    - `kv.not_after_is_checked_before_later_preconditions` (a failing `NotAfter` at index 0 reports index 0 even when a
      later `Equals` would also fail) — every backend
    - `kv.not_after_evaluated_at_apply_not_at_build` (injected clock: build the batch, advance the store clock past
      the deadline, apply → fails; at exactly the deadline → commits) — injectable clocks only
    - `kv.not_after_uses_store_clock_not_caller_clock` (injected store clock behind the caller's: a deadline in the
      caller's past but the store's future commits) — injectable clocks only
    - `kv.not_after_on_refs_only_non_atomic_store` (single ref write + key precondition + `NotAfter`) — gated on
      `atomic_multi_key = false`
  - Capacity: `kv.full_store_rejects_writes_but_serves_reads_and_deletes` (runs where the factory can build a
    capacity-limited store, e.g. `MemoryKv::with_capacity_limit`; skipped with a reason otherwise)
  - Growth: `kv.stats_reports_growth_and_shrink` (put 1,000 keys → `stats.bytes` grows; delete them → it shrinks
    to within 10% of the baseline once the backend's stats are refreshed; R-31)
- **Durability (`dur.*`, R-22):**
  - `dur.cancelled_apply_is_all_or_nothing`: run 200 random multi-key batches, dropping each `apply` future after a
    random number of polls (0..=3). After each, the partition equals either the pre-state or the post-state
    (checked by a full scan against a model), and the store keeps working.
  - `dur.crash_restart_atomic_at_last_commit` (requires `reopen`): apply N batches, record which returned
    `Committed`, drop the store without any clean shutdown (for SQLite: drop the connection mid-series; a backend
    may add a harder kill in its own tests), reopen from the same path, and assert state == the model after exactly
    the committed batches (no torn batch, nothing committed lost).
  - `dur.export_import_roundtrip` (any backend): export a populated partition, import into a fresh store, compare
    full scans.
- **ContentIndex (`idx.*`):** `idx.holder_add_idempotent`, `idx.holder_remove`, `idx.holders_pagination`,
  `idx.hold_blocks_collection`, `idx.expired_hold_allows_collection`, `idx.grace_period`, `idx.block_unblock`,
  `idx.objects_in_different_shards_isolated`.

Where a case encodes today's server behavior, cite the source in a comment (e.g. `kv.first_failing_precondition_index`
is what gives AdvanceRefs its packmap-before-head precedence, `apps/vcs-worker/src/worker_impl/refstore.rs:215-255`).

## Acceptance criteria

- [ ] ≥ 52 named cases (including the six `kv.not_after_*` cases). nextest lists each as its own test (`memory__kv_first_failing_precondition_index`, …).
- [ ] The memory backend passes every case with zero skips except `dur.crash_restart_*` (no `reopen`).
- [ ] A reduced-capability memory store (`RefsOnly`, non-atomic) passes the gated behavior: `Unsupported` is
      returned, nothing is written, and the gated cases skip with a reason.
- [ ] The cancellation and crash/restart cases exist and are generic over any `NamespaceStore` (R-22).
- [ ] The crate is `publish = false` and not reachable from `mkit-cli`.
- [ ] The macro is usable from another crate's `tests/` directory (M0-08/09/11 rely on this). Include a doc example.

## Risks / gotchas

- Cases take the backend by value. A backend that isn't `Clone` must be constructed per case; the factory closure
  handles that.
- Don't use wall-clock sleeps. Time-dependent layouts (expiry indexes) take explicit `now` values.
- Keep cases independent. Use unique ref names and repos per case, so backends backed by one shared file
  (SQLite in M0-09) can run cases in parallel.
