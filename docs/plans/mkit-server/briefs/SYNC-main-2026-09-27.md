## Purpose

`main` gained two changes after `feat/mkit-server` branched:
- **#1136:** `docs/INSTALL.md`, the glibc floor documentation;
- **#1144 (merge commit `2f77982e`):** the security hotfix bounding `PackReader` memory on hostile packs:
  - release bases after last use;
  - lazy zstd;
  - a resident cap of `max(2 × MAX_RAW_OBJECT_SIZE, 16 × pack_len)`, charged before allocation;
  - checked 32-bit framing;
  - no zero-fill of claimed sizes;
  - phase-2 fail-fast and the sequential contention retry.

The feature branch changed the same area:
- **WP-4.1:** the `pack-ruzstd` decode backend and `require_zstd_frame_magic`;
- **WP-4.2:** the `DeltaBaseSource` seam, `decode_entries_with`, `DecodeLimits`/`ChargedBases`/`DecodeBudget`, and
  checked arithmetic;
- **WP-4.8a:** `pack/window.rs`, `decode_payload`, `zstd_claim`, and the shared ruzstd path;
- **WP-5.7a:** `pack/rewrite.rs` and `maybe_compress_capped`.

The feature branch must end up with **both sets of guarantees**.

## A. Fixed (do not change)

1. **Every security property of #1144 holds on the feature branch:**
   - the resident cap is charged before allocation;
   - bases are released after last use;
   - lazy decompression;
   - no zero-fill;
   - fail-fast;
   - the contention retry;
   - checked framing.
2. **Every property of the feature branch holds:**
   - the `DeltaBaseSource` seam and repo-isolated resolution;
   - `DecodeLimits` charged accounting;
   - the ruzstd backend and the frame-magic check on **both** backends;
   - the window reader (`pack/window.rs`) and its equivalence with the buffered reader;
   - the rewrite primitive;
   - `maybe_compress_capped`.
3. **No public API change** to either side's public items. **No new `PackError` variant.** The goldens are unchanged
   (`git diff --exit-code origin/feat/mkit-server -- rust/tests/golden/`).
4. **Both sides' tests exist and pass,** including #1144's new tests:
   - `store_base_is_charged_once_and_released_on_last_use`;
   - `retained_compressed_raw_bases_share_the_resident_cap`;
   - the junk-zstd timing test;
   - contention, skip-after-failure and deferred-error ordering;
   - the ≥ 200 MiB ignored-lane test;
   - the 32-bit framing wasm tests.
5. Specs and docs: keep both. SPEC-PACKFILE §6 takes #1144's resident-cap sentence, with the feature branch's §3.3
   additions kept too.

## B. Decided by the orchestrator (conflict map and resolution rules)

**The `DeltaBaseSource` rule.**
- Feat's `DeltaBaseSource::base(&mut self, id) -> Result<Option<Vec<u8>>, PackError>` can't take the budget-aware
  allocator that #1144 needs for store bases.
- Add a **provided** method, `base_with_allocator` or an equivalently named one, with a default that calls `base()`
  and then charges the result. `ObjectStore`'s implementation overrides it to use `read_with_allocator`, so store
  bases are charged before allocation, as in #1144.
- Existing implementors, including tests and window/rewrite users, keep compiling unchanged.

**Two budgets.** Feat's `DecodeLimits`/`DecodeBudget` (cumulative charged decoded bytes) and main's `ResidentBudget`
(peak resident bytes) are **different limits**, and both apply:
- `PackReader::read` enforces the resident cap;
- `decode_entries_with(…, DecodeLimits)` enforces the cumulative budget;
- where one path runs both, it charges both.

Do not merge them into one type. Do document how they relate, in a comment on each.

- `docs/INVARIANTS.md`: keep both.

## Tests (required, in addition to both sides' existing tests)

1. **The #1144 DoS probe** (junk `0x03`/`0x04` entries claiming 1 GiB, N=16/64/256) on **both** backends:
   - native C zstd (`--all-features`);
   - `--no-default-features --features pack-ruzstd`.

   Both must be millisecond-scale in release. Record the timings in the PR body.
2. **Window vs buffered equivalence** on the merged decoder, over the existing goldens and the proptest.
3. **A store base charged through `DeltaBaseSource`:** a delta whose base comes from the `ObjectStore` is charged
   before allocation, and released on last use (#1144's test, run through the feature branch's seam).
4. **Both budgets:** a pack that fits the resident cap but exceeds `DecodeLimits` fails with the `DecodeLimits` error,
   and the converse holds too.
