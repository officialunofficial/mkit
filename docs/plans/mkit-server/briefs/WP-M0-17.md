- **Milestone/track:** M0
- **Base:** `feat/mkit-server`; **branch:** `mkit-server/wp-m0-17-vcs-worker-port`
- **Depends on:** M0-06, M0-07, M0-16

- **Open-question dependency:** Q8 (the job lives in `workers.yml`, which triggers only on `main`; during the epic the check runs locally), Q13, Q17 (800 KiB download chunks)

## Conventions

Same as WP-M0-01: TMPDIR, trailer, no CI polling, no proto change, a size check, workspace lints. Worker gate:
`(cd apps/vcs-worker && cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo clippy --target wasm32-unknown-unknown --all-targets -- -D warnings && cargo test --lib)`.

## Goal

Make `vcs-worker` a thin reference deployment (PRD §5.1):

- `#[event(fetch)]` → the shared adapter: CORS, body cap, `worker::Request`↔`http`, `mkit_server::connect::service`
  over `Pipeline<R2BlobStore, DoNamespaceStore, Hooks>`
- `#[durable_object] RefStore` → `mkit_server_worker::ns_object::handle`

Delete every duplicated module. Prove "no wire change" by running the M0-07 wire suite against `wrangler dev` locally
(`scripts/vcs-worker-conformance.sh`, output in the PR; the M0 exit criterion). Also add a `workers.yml` job that runs
the same script. `workers.yml` triggers only on `main` (push and PRs to `main`), so the job runs for the first time on
the final PR to `main`; don't widen its triggers to the feature branch.

## PRD refs

§5.1 (`vcs-worker` becomes a thin reference deployment), §8 M0 (port vcs-worker; conformance passes on
`wrangler dev`; nothing changes on the wire), D1, D34.

## Files

- `rust/crates/mkit-server-worker/src/adapter.rs` (wasm-only):
  ```rust
  pub struct WorkerConfig { pub audience: String, pub repository: String, pub max_body_bytes: usize, pub blob_binding: &'static str, pub ns_binding: &'static str }
  impl WorkerConfig { pub fn from_env(env: &worker::Env) -> Result<Self, worker::Error>; }   // AUTH_AUDIENCE / AUTH_REPOSITORY (auth.rs:21-32 parity: missing → unavailable)
  pub async fn serve(req: worker::Request, env: worker::Env, cfg: &WorkerConfig) -> worker::Result<worker::Response>;
  ```
  The body of `serve` is today's `serve_connect` (`apps/vcs-worker/src/worker_impl.rs:60-106`), **except that
  request and response bodies stream** (reconciliation R-25; today's `read_capped_body`/`respond_buffered` hold the
  whole pack in a 128 MB isolate shared by every request). **Streaming dispatch path (normative for this WP; review
  01, R-66):**
  - `is_options_preflight` → `cors_preflight_response(mkit_server::auth_v2::CORS_ALLOW_HEADERS, "POST, GET, OPTIONS")`
  - **Request body:** build the `http::Request` with a streaming body, never `Full<Bytes>`: take the request's
    `worker::Body` (workers-rs 0.8.6 `http` feature; `http/body.rs:19-22` declares it `Send + Sync`, so it meets
    connectrpc's `B: Body<Data = Bytes> + Send + 'static` bound, `service.rs:1613-1617`). Its error type
    `worker::Error` holds a `JsValue` and is `!Send`, so wrap the body with `http_body_util::BodyExt::map_err` into a
    local `BodyError(String)` that is `Send + Sync + std::error::Error` (connectrpc requires `B::Error: Error + Send +
    Sync`), then with a byte-counting limiter that fails the stream past `max_body_bytes` (the same 400 JSON body as
    `body_too_large`, `worker_impl.rs:69-76`, when it trips before dispatch). Unary RPCs are collected by connectrpc
    itself (they're small; the unary cap is 1 MiB).
  - **Headers:** copy them with `copy_headers_filtered(.., |k| !is_deadline_header(k))` (keep stripping the Connect
    timeout headers: the client-streaming path calls `Instant::now()`, connectrpc `service.rs:2767`, which panics on
    wasm32).
  - **Dispatch:** a generic-body variant of `dispatch_oneshot` (`dispatch_oneshot_body<S, B>(svc, http::Request<B>)`,
    in `mkit-server-worker/src/adapter.rs`; optionally upstreamed additively to `mkit-worker-common`), because the
    existing `dispatch_oneshot` is typed to `http::Request<Full<Bytes>>`. connectrpc 0.9 reads client-streaming
    bodies incrementally: `spawn_body_reader` (`service.rs:3078-3130`) runs through `spawn_detached`, which is
    `wasm_bindgen_futures::spawn_local` on wasm32 (`lib.rs:186-193`), into a bounded `mpsc(1)`, so memory is bounded
    by one `UploadPack` chunk.
  - **Response body:** always `respond_streamed` (`mkit-worker-common/src/adapter.rs:148`; `ConnectRpcBody::Error =
    Infallible`) + `copy_response_headers` + `with_cors`. **Never `respond_buffered`, and never a buffered
    `dispatch_oneshot` for a streaming RPC** (`UploadPack`, `DownloadPack`); `DownloadPack` streams chunk by chunk.
  - **Fallback (only if the path above fails on wasm32 with a minimal reproduction recorded in the PR):** the adapter
    parses the Connect streaming envelopes for `UploadPack` itself (5-byte prefix: flags + big-endian length, then
    the message; end-of-stream frame) directly from `request.body` and calls `UploadSession::push` per message /
    `finish` at the end, building the response envelope itself. The wire stays identical and nothing buffers a
    whole pack. Don't reintroduce whole-body buffering in any case. The 64 MiB cap stays only as a documented
    stopgap until M1 parts (which bypass the DO and stream per part).
  - build the `Pipeline` with:
    - `AuthMode::AuthV2`
    - `write_quota: Some(DEFAULT_WRITE_QUOTA)`
    - `upload_limits.max_total_bytes = 64 MiB` (documented M1 stopgap)
    - `R2BlobStore` (streaming, M0-16)
    - `DoNamespaceStore` (placement none)
    - `WorkerClock`
    - under `test-faults` only: a `FaultHooks` impl mapping `x-mkit-test-fault: after-reserve|after-put` to M0-05b
      fault points, plus the M0-16 store faults (vcs-worker parity; R-11)
  - `dispatch_oneshot_body(mkit_server::connect::service(Arc::new(pipeline)), http_req)` → `respond_streamed` +
    `copy_response_headers` + `with_cors` (the streaming path above)
  - `pub async fn ns_object_fetch(state: &worker::State, req: worker::Request) -> worker::Result<worker::Response>`
    (wraps `ns_object::handle` with a lazily constructed `DoSqlConn`)

## Risks / gotchas

- `worker-build` compiles vcs-worker from `apps/vcs-worker` with its own `Cargo.lock`. It now pulls `mkit-server*`
  path deps from `rust/`, so make sure nothing enables `mkit-core`'s default `pack-zstd` feature in that graph.
- Instant panics: keep `is_deadline_header` filtering (`mkit-worker-common/src/adapter.rs:55`). The Connect timeout
  header would panic on wasm.
- The DO-level error mapping changes. Today any DO failure surfaces as `invalid_argument "refstore …"`
  (`service.rs:144-151`). Now typed outcomes map through the pipeline. If the wire suite shows a code change for an
  **infrastructure** failure only, that isn't covered by the "no wire change" contract, but call it out in the PR.
- The wrangler dev cold start is slow. Give the health wait a generous timeout, and fail with logs attached.
