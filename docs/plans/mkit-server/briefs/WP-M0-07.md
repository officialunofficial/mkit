# WP-M0-07: Black-box wire conformance suite (skeleton covering today's behavior) + runner

- **Milestone/track:** M0
- **Base:** `feat/mkit-server`; **branch:** `mkit-server/wp-m0-07-wire-suite`
- **Depends on:** M0-03, M0-06
- **Size:** L (~1100–1400 lines)

## Conventions

Same as WP-M0-01: TMPDIR, trailer, no CI polling, no proto change, a size check, workspace lints.

## Goal

Build part (b) of `mkit-server-conformance` (PRD §5.1): a black-box suite that takes a base URL and a profile
(auth mode, signer, capabilities). It drives any `mkit.transport.v1` server over real HTTP and pins **today's**
observable behavior. It becomes the M0 "no wire change" oracle. Ship a runner binary so the same suite runs against
`wrangler dev` (M0-17), staging (M1) and third-party servers.

## PRD refs

§5.1 (conformance row: CAS, atomic advance, replay, upload rejections; the later cases are listed and reserved),
§8 M0 exit ("Nothing changes on the wire"; conformance on native and `wrangler dev`), D1.

## Scope

**IN:** `src/wire/` (client helpers, signer, profile, cases, runner); `src/bin/mkit-server-conformance.rs`
(`wire` subcommand); two automated baselines in `tests/`; a documented manual baseline against today's vcs-worker.

**OUT:** cases for M1+ features. Reserve their names in a `// TODO(M1..M5)` list: multi-repo isolation, namespace
policy, tickets, grants, admission, published view, leases/GC, takedown, receipts. Don't write stubs that pass
vacuously.

## Files

Create in `rust/crates/mkit-server-conformance/`:
- `src/wire/mod.rs`: `WireTarget { base_url: url::Url, profile: Profile }`, `run(target, filter) -> Report`
- `src/wire/profile.rs`: see Design; also loadable from TOML (`--profile path.toml`) or flags
- `src/wire/client.rs`: thin raw client over `connectrpc` client + `mkit_transport_connect::generated` message types
  (`#[doc(hidden)] pub mod generated`, `mkit-transport-connect/src/lib.rs:62-66`), with per-call headers
  (`CallOptions::with_header`). It must be able to send deliberately *invalid* requests (bad expectation, wrong
  offsets, reused nonce), which `ConnectTransport` can't do.
- `src/wire/sign.rs`: auth v2 envelope builder over `mkit_core::write_auth::Operation` + `ed25519-dalek`. It exposes
  `SignedOp { headers, nonce }`, so cases can replay the exact same headers.
- `src/wire/cases/{refs.rs, advance.rs, packs.rs, upload.rs, download.rs, auth.rs, replay.rs, quota.rs, health.rs}`
- `src/wire/report.rs`: per-case Pass/Fail(msg)/Skip(reason); TAP-like stdout; exit code 1 on any Fail
- `src/bin/mkit-server-conformance.rs`: `mkit-server-conformance wire --base-url URL [--profile FILE] [--auth none|bearer|auth-v2] [--bearer-token-env VAR] [--audience ORIGIN] [--repository ID] [--signer-seed-hex HEX|--random-signer] [--atomic-advance] [--max-pack-bytes N] [--quota-ops N --quota-bytes N] [--milestone M0..M5] [--features a,b,..] [--filter SUBSTR]`
- `tests/baseline_legacy_connect.rs`: starts today's native server in-process
  (`mkit_transport_connect::router(Arc::new(FileTransport::new(tempdir)))`, which is exactly what
  `mkit serve --http` serves (`serve/http.rs:150-172`); `router` is at `mkit-transport-connect/src/lib.rs:94`;
  served by `axum::serve` on `127.0.0.1:0`) and runs profile `none`, `atomic_advance=false`. It records that the
  legacy server passes. **M0-15 deletes this test** when the `server` feature is removed; say so in a comment.
- `tests/baseline_pipeline_memory.rs`: serves `mkit_server::connect::service(pipeline)` over axum (dev-dep) with
  memory stores and runs three profiles: `none`, `bearer`, and `auth-v2` + quota + atomic.

Cargo (dev and normal): `mkit-transport-connect = { path = "../mkit-transport-connect" }`;
`connectrpc = { version = "0.9.0", default-features = false, features = ["client", "gzip", "json"] }`, plus
`server` and `axum` in dev-deps for the baselines; `ed25519-dalek`, `url`, `clap` (derive), `toml`, `serde`, `hex`;
dev-deps `axum`, `mkit-transport-file`, `tempfile`, and `mkit-transport-connect` with `features = ["server"]`.

## Design

```rust
pub struct Profile {
    pub auth: WireAuth,                 // None | Bearer { token } | AuthV2 { audience, repository, seed: [u8; 32] }
    pub atomic_advance: bool,           // true: head/packmap conflicts leave BOTH refs untouched
    pub max_pack_bytes: u64,            // oversize case uses max+1
    pub quota: Option<QuotaLimits>,     // enables quota.* cases (use a tiny quota only against disposable servers)
    pub run_id: String,                 // random; every ref name is namespaced "refs/heads/conformance/<run_id>/<case>"
    pub milestone: Milestone,           // highest milestone whose cases run (default: M0)
    pub features: BTreeSet<Feature>,    // derived from the flags above in M0
}
/// Milestone tag + feature requirements per case (reconciliation R-12). A case runs only if the profile's
/// milestone >= the case's, and every required feature is in `profile.features`. From M1 on, the runner fills
/// `features` from `GetServerInfo` (WP-1.6) unless `--features` overrides it; in M0 it comes from flags/TOML.
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord)] pub enum Milestone { M0, M1, M2, M3, M4, M5 }
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)]
pub enum Feature { AtomicAdvance, Replay, Quota, TestFaults /* server built with test-faults */, MultiRepo, Tickets,
                   Grants, SignedReads, Admission, IndexedMode, HttpObjects, Leases, Takedown, Receipts, Admin }
pub trait Case { const NAME: &'static str; const MILESTONE: Milestone; const REQUIRES: &'static [Feature];
                 fn requires(p: &Profile) -> Result<(), &'static str /*skip reason*/>; async fn run(t: &WireTarget) -> Result<(), String>; }
```

Cases. Assert **Connect codes and typed outcomes**, never message text:

- **refs:** `refs.read_missing`, `refs.update_any_then_read`, `refs.update_missing_conflict_failed_precondition`,
  `refs.update_match_conflict_failed_precondition`, `refs.update_unspecified_invalid_argument`,
  `refs.update_any_with_expected_id_invalid_argument`, `refs.invalid_ref_name_invalid_argument`,
  `refs.list_prefix_stripped`, `refs.list_invalid_prefix_invalid_argument`, `refs.new_id_wrong_length_invalid_argument`
- **advance:** `advance.committed`, `advance.head_conflict_typed`, `advance.packmap_conflict_typed`,
  `advance.atomic_both_untouched` (requires `atomic_advance`), `advance.nonatomic_packmap_first` (requires
  `!atomic_advance`)
- **packs:** `packs.exists_false_then_true`, `packs.pack_id_wrong_length_invalid_argument`
- **upload:** `upload.roundtrip_multi_chunk` (3 chunks, then download and compare bytes and BLAKE3),
  `upload.empty_pack`, `upload.first_not_header_invalid_argument`, `upload.second_header_invalid_argument`,
  `upload.offset_gap_invalid_argument`, `upload.overrun_invalid_argument`, `upload.no_last_invalid_argument`,
  `upload.declared_mismatch_invalid_argument`, `upload.hash_mismatch_not_stored` (also `PackExists` stays false),
  `upload.oversize_resource_exhausted`, `upload.rejected_never_overwrites_existing` (upload good, then bad bytes for
  the same id, then download still good)
- **download:** `download.not_found_before_any_message`, `download.chunks_contiguous_ending_last`
- **health:** `health.serving`, `health.unknown_service_not_found`
- **auth (bearer):** `auth.bearer_missing_unauthenticated`, `auth.bearer_wrong_unauthenticated`,
  `auth.bearer_applies_to_streaming`
- **auth (auth-v2):** `auth.v2_missing_headers_unauthenticated`, `auth.v2_wrong_audience`, `auth.v2_wrong_repository`,
  `auth.v2_body_digest_mismatch`, `auth.v2_expired`, `auth.v2_version_not_2`, `auth.v2_pack_commitment_mismatch`,
  `auth.v2_reads_unsigned_ok`
- **replay:** `replay.same_op_returns_saved_result_after_ref_moved` (the `auth_v2.mjs` a, b, a sequence),
  `replay.concurrent_duplicates_all_succeed` (16 parallel), `replay.nonce_reuse_different_op_invalid_argument`,
  `replay.advance_replay_equals_first_result`, `replay.upload_replay_succeeds`
- **quota:** `quota.ops_exhaustion_resource_exhausted`, `quota.exhaustion_allocates_no_replay`
- **growth** (requires `TestFaults`; R-31): `growth.replay_and_quota_pruned` (load, then clock-skew past the windows,
  then a probe write; the server's `stats` for the partition, exposed under `test-faults` at
  `GET /__mkit_test/stats`, shrinks back). M1 extends this group to tickets and outbox (WP-1.27).
- **list** (M0 has no ListRefs pagination on the wire; M1 adds it): `list.large_response_within_limit` records the
  response size for 10,000 refs so M1 can assert the 32 MiB bound (WP-1.27).

without writing it up.

## Acceptance criteria

- [ ] ≥ 45 wire cases. Every case name is stable and documented in `src/wire/mod.rs`.
- [ ] Both automated baselines pass. The pipeline baseline passes every non-skipped case. The legacy baseline passes
      every non-skipped case, except those in an explicit `LEGACY_DIVERGENCES: &[(&str /*case*/, &str /*why*/)]`
      list. Each entry must be justified in the PR, and the list should ideally be empty.
- [ ] The manual `wrangler dev` report is in the PR, with every divergence explained.
- [ ] No case depends on message text or chunk count.
- [ ] The runner exits non-zero on failure and prints a per-case summary.
- [ ] The reserved-case TODO list is present, each entry tagged with its milestone and feature.
- [ ] Every case declares `MILESTONE` and `REQUIRES`; the report prints skips with the missing feature.

## Risks / gotchas

- The auth v2 body digest is BLAKE3 of the **exact encoded request bytes**. Encode once and both sign and send those
  bytes.
- `x-audience` must equal the server's configured audience byte for byte (`validate_audience` canonical form: no
  default port, lowercase).
- Unique ref names per run so the suite can run repeatedly against a persistent server. Never delete refs
  (UpdateRef has no delete verb).
- The quota cases exhaust the signer's hourly budget. Use a dedicated random signer per quota case, and only enable
  the cases when the profile declares a tiny quota.
