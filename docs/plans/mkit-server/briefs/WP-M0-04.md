(PRD §4 "Duplicated logic"). Port the **union** of the existing tests. Existing consumers are **not** switched in

depend on `mkit-server` early.

## Design notes

- Error-code fidelity. Today the Connect paths map an oversize declared total to `resource_exhausted`
  (`pack.rs:73-77`, `service.rs:408-411`), and every other framing error to `invalid_argument`. The ssh path uses
  `ErrorCode::InvalidRequest` for all of them. The ssh binding (M0-12) maps codes itself, so `UploadError::code()`
  returns the Connect-side code and `ssh_message()` stays verbatim.
- Caps: the Connect native cap is `PACK_BODY_LIMIT` (4 GiB, `protocol.rs:223`). The ssh cap is
  `MAX_BYTES_PER_CONN` (1 GiB, `serve/mod.rs:137`) with a chunk cap of `MAX_FRAMES_PER_CONN`. The Workers cap is
  64 MiB (`service.rs:71`). They are all `UploadLimits` supplied by the binding; no constant is hard-coded in
  `upload.rs`.
- `strip_listed_prefix` must keep vcs-worker's behavior: strip only when the prefix matches, otherwise return the
  name unchanged. The comment at `service.rs:196-210` explains why the CLI depends on this. Copy that rationale.

## Risks / gotchas

- `write_auth::verify_headers` runs `Operation::verify`, which uses `verify_strict`. Don't reimplement any of it.
  `auth_v2.rs` is glue only.
- Don't hash in `UploadValidator`. Double hashing a 4 GiB pack doubles CPU on the hot path, and the sink owns the
  BLAKE3 guarantee.
- vcs-worker's `ce_invalid` wraps DO errors as `invalid_argument` with "refstore {op}: {msg}" (`service.rs:150`).
  That is transport glue and stays out of `storage_error.rs`. M0-17 decides the mapping from pipeline outcomes
  instead.
